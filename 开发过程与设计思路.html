NO.01

《Chrono Loop》时间循环解谜

游戏设计已完成 UnityC#Aseprite时间回溯

概述

独立开发的 Unity 时间循环解谜游戏，从创意构思、玩法设计到可玩版本全流程一人主导，同时承担程序实现与像素美术。核心卖点是「时间回溯」——不是把回溯当作附加技能，而是把它当作整个解谜循环的地基。

开发过程

概念阶段：先用纸面原型界定回溯的规则边界——回溯多长、回溯后哪些状态保留、哪些重置。这一步决定了后续所有关卡设计的前提，也避免了「机制听起来酷但玩起来空」的陷阱。

实现阶段：用 Unity + C# 完成交互逻辑与回溯系统的搭建；美术用 Aseprite 逐帧绘制，保持统一的像素视觉语言，让玩法与美术在同一套审美体系里。

调优阶段：结合用户认知心理设计阶梯式关卡难度——前期用单点回溯做教学，中后期叠加多段回溯与移动平台，难度按认知负荷渐进；全程用即时反馈（残影、音效、结算表现）降低试错挫败感。

设计思路

把「失败—回溯—重来」变成正反馈循环：玩家不会被一次失误惩罚，而是获得重新规划行动的机会。相比传统解谜的「一次答对」，它鼓励的是探索与试错——这也正是时间循环题材最适合承载的情绪。

复盘

验证了「一个人也能完成从玩法设计到美术交付的全流程」。后续可扩展的方向是让回溯影响更多游戏状态（敌人位置、机关状态），从「角色回溯」升级为「世界回溯」。

NO.02

AI 辅助横版肉鸽游戏

游戏设计已完成 PythonPygame行为树项目管理

概述

4 人团队 Pygame 横版肉鸽游戏。我担任项目负责人，负责 AI 敌人系统与动态难度设计，并用 Trello 协调团队按期交付可玩版本。

开发过程

项目推进：用 Trello 把任务拆到可执行粒度、跟进里程碑，协调程序 / 美术 / 策划的依赖关系，保证团队按时交付完整可玩版本。

AI 实现：为敌人设计行为树，实现巡逻 / 追击 / 攻击 / 逃跑的状态迁移，行为选择依赖玩家距离、血量等实时状态，让敌人既有规律可循又有应对变化的能力。

动态难度：实现基于玩家操作习惯的难度自适应——根据生命值、失误率、通关速度等指标实时调整敌人密度与攻击频率，让挑战始终贴合玩家当前水平。

设计思路

「AI 难度自适应」是这次的核心命题：难度不该是写死的曲线，而应跟随玩家表现动态调整——新手不被劝退、老手不感无聊。行为树的引入让敌人行为可预测又有多样性，是难度系统能落地的基础。

复盘

内测数据显示游戏体验满意度提升 32%，验证了自适应难度的价值。项目管理层面，Trello 看板把 4 人协作的沟通成本显著降了下来——这让我意识到：游戏开发里「怎么组织人」和「怎么写代码」同样重要。

NO.03

Blender 3D 数字内容创作

视觉研究已完成 BlenderCyclesPython材质渲染

概述

以桌面静物为对象的 3D 数字创作。负责核心模型（桌面与杯具）建模、半透明材质调试与渲染优化，并通过 Python 脚本实现场景自动化搭建与渲染控制。

开发过程

建模：桌面与杯具是画面主体，重点在于比例、结构与轮廓的高还原，先做粗模确定构图，再逐步细化。

材质：半透明材质（玻璃与液体）是主要难点——通过多层材质节点叠加透射与折射，配合布光反复调试，才获得通透而不发灰的质感。

脚本化：用 Python 脚本实现场景自动化搭建、镜头路径动画与批量渲染控制，把可重复的机械劳动交给工具，把精力留给不可自动化的艺术打磨。

设计思路

采用「程序化 + 手动精修」的结合：脚本处理批量、可复现的部分（搭建、渲染、路径），手动处理需要审美判断的部分（材质、打光、构图）。这也是我在 3D 工作流里最舒服的协作方式。

复盘

通过这个项目系统掌握了 Blender Python API 与 Cycles 渲染管线，也意识到「技术工具化」对艺术产出的效率提升——同一套脚本可以复用到后续任何场景类创作。

NO.05

YOLOv8 车型识别系统

视觉研究已完成 PythonYOLOv8OpenCV数据增强

概述

目标是在资源受限的边缘设备上实时识别小米 SU7 车型。采用「正反样本」策略构建数据集、对比 YOLOv8n / s 训练，并导出 ONNX 完成跨平台部署。

开发过程

数据：采用「正反样本」策略构建 1100 张数据集（700 张 SU7 + 400 张相似车型），按 90/5/5 划分训练 / 验证 / 测试。

训练：对比 YOLOv8n（3M 参数）与 YOLOv8s（11M 参数）两个模型：统一 640×640 输入、300 轮训练，验证小数据集下 nano 模型已达到最优性价比。

部署：导出 ONNX 解除框架依赖，支持跨平台边缘部署，为「小样本 + 轻量模型」的落地方案提供完整链路。

设计思路

正反样本策略让模型学会区分「SU7 与相似车型」而非「车与非车」，这是识别任务的真正难点；轻量模型优先，因为目标设备资源受限——精度够用即可，部署成本与帧率才是硬约束。

复盘

系统走完了「数据构建 → 训练对比 → 轻量化 → ONNX 部署」的完整链路，理解了真实项目中「数据质量」和「部署约束」往往比模型结构更能决定成败。

NO.06

RTSP 流媒体服务器

互动媒体已完成 PythonSocketRTSP/RTP多线程

概述

从零构建支持多客户端连接的 RTSP 流媒体服务器（不依赖现成库），完整实现协议核心命令，支持多客户端并发连接与稳定视频流传输。

开发过程

协议：完整实现 OPTIONS、DESCRIBE、SETUP、PLAY、TEARDOWN 五个核心命令，把 RTSP 状态机按 RFC 规范逐条落地。

会话：设计会话管理机制，为每个会话动态生成符合标准的 SDP 描述文件，保证不同客户端各自独立、互不干扰。

并发：基于 Socket + 多线程处理多客户端连接，用 FFplay / VLC 实测验证：延迟 <200ms、30FPS 稳定传输。

设计思路

先啃协议再写代码——把每个命令的合法状态迁移画成状态图，再按图实现，避免「看似能跑、实则不符合规范」。会话与 SDP 的动态生成则保证了服务器不是为单客户端定制的玩具。

复盘

深入理解了流媒体协议栈（RTSP / RTP / SDP）与网络并发编程，也体会到「协议合规」在系统类项目里是质量底线。

NO.07

《Chrono Loop Web》时间回溯原型

互动媒体可试玩 HTML5CanvasJavaScript时间回溯

概述

把《Chrono Loop》的时间回溯核心机制移植为浏览器可玩原型，用 Web 端验证「试错—倒带—重来」玩法循环的可行性，面试官可直接在浏览器里试玩。

开发过程

状态记录：按帧把角色状态写入 5 秒环形缓冲，轻量实现「可回放的历史」，无需存档系统。

回溯表现：死亡后自动回溯 2.5 秒（2 倍速倒带），R 键可手动回溯 3 秒，倒带期间呈现残影拖尾与回流光点粒子，把「时间倒流」做成可见可感的效果。

关卡与修复：含移动平台、尖刺陷阱与 EXIT 终点；开发中修复了历史耗尽兜底、按键残留等边界问题，并补充移动端触控虚拟按键与画布自适应。

设计思路

用环形缓冲而非完整存档，是因为「最近几秒」恰好覆盖试错窗口；自动回溯 2.5 秒 + 手动 3 秒形成「被动救场 + 主动操作」两种回溯节奏。整个原型的目标是让人 30 秒内理解核心循环。

复盘

验证了核心机制在 Web 端的可行性，也暴露了边界状态（历史耗尽、按键冲突）在回溯类玩法里必须提前设计——这正是从原型走向正式作品的关键经验。

NO.08

XV6 MLFQ 调度器实现与可视化分析

系统工程已完成 CXV6MLFQ内核开发Python可视化

概述

本科毕业设计：在 XV6 教学内核中从零实现多级反馈队列（MLFQ）调度器，替换默认 Round-Robin，并用 Python 可视化真实调度日志做实验验证。

开发过程

PCB 扩展：直接修改 XV6 内核（proc.h / proc.c / trap.c），扩展进程控制块新增 queuelevel（0–2 优先级）、ticksinqueue、wait_ticks 三个字段。

调度器：完全重写 scheduler() 实现 3 级优先级队列：新进程默认进入 Q0，CPU 密集型进程用完时间片自动降级，I/O 密集型进程因频繁等待保留高优先级。

防饥饿：引入基于定时器的 anti-starvation 机制，防止低优先级进程长期得不到调度。

可视化：构建 Python 可视化框架，从系统日志生成甘特图（MLFQ 降级过程）与对比柱状图（CPU vs I/O 优先级保留），用真实运行数据验证设计。

设计思路

MLFQ 的核心是「经验驱动的优先级调整」：不依赖静态优先级，而是根据进程的实际行为（CPU 密集还是 I/O 密集）动态调整，从而在交互响应与 CPU 吞吐之间取得平衡。可视化的意义在于——调度器是对是错，日志不会说谎。

复盘

实验验证 MLFQ 对交互型进程的响应速度显著优于默认 Round-Robin。这个项目把操作系统教材里的调度理论完整落到内核代码上，是我对「系统底层」理解最深的一次实践。

NO.11

《脉冲星场》交互式声景生成器

互动媒体可试玩 Web AudioCanvas 2D生成式艺术音画交互

概述

以「深空仪器」为概念的交互式声景生成器：点击 / 拖动夜空即生成粒子星尘并实时合成音符，横坐标定音高、纵坐标定力度，把画布变成一件可以演奏的乐器。

开发过程

音画映射：横坐标映射 A 小调五声音阶音高，纵坐标映射力度，青 / 紫 / 品 / 金四相色随音符轮转——位置、颜色、声音三者在同一坐标系里统一。

声音合成：全部声音由 Web Audio 原生合成（零采样依赖），四类合成音色（星弦 / 空鸣 / 脉动 / 风铃）覆盖不同演奏气质。

自走作曲：内置 92BPM 巡航作曲器（i–VI–III–VII 和声进行），底鼓 / 踩镲 / 贝斯 / 旋律四轨以音频时钟 lookahead 调度，音画严格同步。

工程化：单文件零依赖；静音开关常驻、尊重 reduced-motion、移动端触控适配，支持 ?demo=1 无声预览模式。

设计思路

五声音阶的选择保证「任意点击都好听」——没有黑键，也就没有难听的音；lookahead 调度避免音频时钟漂移，让节奏严格稳定。整个作品的定位是「演奏」而非「播放」：用户的操作直接产生音乐，而不是触发预设片段。

复盘

验证了「零采样、纯合成」的生成式音频方案在 Web 端的可行性与表现力；对音频调度、音高映射与音画同步有了完整的实践认知。

NO.12

《星尘捕手》交互式收集游戏

游戏设计可试玩 HTML5Canvas 2DWeb Audio粒子系统程序化音频

概述

以「接住坠落星辰」为核心循环的休闲街机收集游戏：移动泡泡接住金色星辰累计连击，青色稀有星辰提供高额奖励，红色流星碰撞损失生命——一个完整而紧凑的反馈闭环。

开发过程

核心循环：接住金色星辰累计连击与得分；青色稀有星辰高额奖励；红色流星扣命。游玩时间越长，星辰生成越密、下落越快，难度随时间自然渐进。

反馈设计：接星伴随吸入动画、粒子爆裂与屏幕震动，连击每 5 次触发得分倍率提升——每一次操作都有即时的音画回报。

音频与数据：背景音乐与全部音效由 Web Audio 实时合成（零采样依赖）；最高纪录持久化保存在本地，给重复游玩一个可超越的目标。

工程化：单文件零依赖，支持 ?demo=1 静置预览模式，无需操作即可直接展示画面与音效。

设计思路

「简单规则 + 密集反馈」是街机式体验的配方：玩法一句话能讲清，但反馈密度让每次接星都有满足感。连击倍率与稀有星辰则提供了「追求最优路线」的钩子，把休闲操作变成轻度的技巧挑战。

复盘

在脉冲星场之后第二次实践程序化音频与粒子系统，反馈闭环的打磨更加熟练；也验证了「单文件零依赖」的交付方式非常适合放进作品集直接展示。

NO.13

《岔路 Branch Road》LLM 即时分支叙事游戏

游戏设计原型 LLMAI 叙事分支叙事TTSCogView

概述

基于 LLM（glm-4-flash）即时生成分支的叙事游戏竖切 0.1（好玩验证版）：框架固定、分支即生，验证「AI 即时生成」能否撑起叙事沉浸感。

开发过程

叙事框架：末班地铁 / 林晚的手机 / 23:47 定时草稿 / 终点站四条线索渐次暗示，叙述者永不点破——框架固定，但分支由 LLM 即时生成，每次游玩都不同。

玩法：每回合现生成行动选项，同时支持自由输入直接行动；8 回合抵达结局后可回看「如果你做了另一个选择」的平行结局。

表现：终点站弹出 23:47 那封信的信卡，由 edge-tts 女声朗读；CogView 预生成 8 张场景图随剧情切换、游玩零等待。

验证：内置探针埋点，验证核心命题「你会不会想知道另一种选法？」——用真实游玩数据检验设计假设。

设计思路

「框架固定、分支即生」是对 LLM 叙事的务实取舍：不追求无限开放的沙盒，而是用固定框架保证叙事质量下限，用 LLM 生成保证每次游玩的差异性。自由输入让玩家真正「行动」，而不是在预设选项里做选择题。

复盘

验证了 LLM 生成式叙事的沉浸感与成本可行性，也发现「AI 生成 + 人工框架」的混合模式是当下最稳的路径；探针埋点证明了数据驱动设计在叙事游戏里同样有效。

NO.14

《抉择的房间》分支叙事游戏

游戏设计可试玩 JavaScript分支叙事多结局零依赖

概述

纯前端分支叙事游戏，零依赖零构建、双击即玩。4 章 18 结局 18 线索，内容全部 config 驱动、引擎零改动，把「多结局叙事」当作一套可测试的系统来设计。

开发过程

叙事结构：4 章 18 结局 18 线索，包含第四章源头真结局（链式双线索）、真结局尾声（回访地基）、陷阱门控（假终结·双刃剑）、出口陷阱（伪出口·绕圈）、分歧点 × 陷阱合流等结构设计。

系统：内置线索图鉴与结局图鉴（收集进度本地保存）、分歧点提示——把「收集」做成重复游玩的动力。

可测试性：提供「运行回归测试」按钮，随时自检剧情图完整性，防止多结局逻辑穿帮。

架构：全部内容 config 驱动，引擎零改动即可扩展新剧情——内容与逻辑分离，便于维护与迭代。

设计思路

把多结局当成「图」来设计：节点是场景、边是选择，陷阱与真结局都是图结构的一部分。图鉴系统让「看到全部结局」成为可量化的收集目标；回归测试则把叙事结构从「手写的剧本」升级为「可验证的图」。

复盘

「内容 config 驱动 + 引擎零改动」的架构让创作与开发彻底解耦，也让我意识到：叙事复杂度的增长必须靠结构管理，而不是靠更多的手工分支代码。

NO.15

《生生不息》互动媒体艺术游戏

互动媒体原型 生成式音频自动演化互动媒体HTML5

概述

以「自动演化 + 生成式音频」为核心的互动媒体艺术游戏：屏幕中的生灵群落随时间自动演化，玩家通过移动与点击注入能量、引导生长方向，声音随生灵状态实时生成。

开发过程

演化系统：生灵群落按规则随时间自动演化——出生、生长、繁衍、消亡，构成一个自主运转的微型生态。

玩家介入：玩家不是直接控制个体，而是通过移动与点击注入能量、引导生长方向——「弱控制，强引导」的交互模式。

生成式音频：声音随生灵状态实时变化，群落越繁荣、声音越丰富，形成状态与听觉的直接映射。

模式：支持多模式切换（1–4）、声音开关（M）与暂停（空格），让观者可以选择观看或参与。

设计思路

探索的是「生命循环与演化」主题下玩家的另一种角色：不是全知全能的控制者，而是生态系统里的一个能量来源——玩家的存在会影响演化方向，但无法决定每个生命的细节。这比「玩家 = 主角」的常规设定更有艺术表达空间。

复盘

这个作品是我在「交互艺术的玩家角色」上的一次实验：结论是「放手的控制」同样能带来强烈的参与感，也为后续互动媒体艺术项目提供了新的方向参考。

NO.16

Co-Desk 联机共创自习桌

系统工程已完成 ElectronReactFastAPIWebSocketSQLite

概述

人机交互课程项目的可运行版本（MVP）：Electron + React 桌面客户端连接 FastAPI 云端后端，SQLite 保存任务、房间与专注记录，把「和同伴一起自习」做成真正可互联网联机的产品。

开发过程

观察与定义：从「一个人自习太孤独」的观察出发，把远程自习做成联机陪伴场景——同伴座位、专注状态、鼓励卡实时同步，让隔着屏幕的学习也有在场感。

架构：Electron + React 桌面端；FastAPI 后端服务；SQLite 数据库自动建表；后端设计为可部署云端的架构（HTTPS REST + WSS WebSocket），客户端填入云端地址即可跨设备同房间实时同步。

功能落地：自习房间列表与自定义房间、账号注册登录（密码哈希存储）、番茄钟、任务便利贴与任务拆解、环境音模拟与座位方向试听、鼓励卡轻互动、专注记录统计与自习时间排行榜。

验证与分发：用双客户端模拟脚本做 10 项联机断言（加入 / 同伴列表 / 状态同步 / 心跳 / 广播 / 退出回落）全部通过；打包 win-x64 分发版。

设计思路

核心命题是「陪伴感」：联机不只是聊天，而是让「和同伴一起努力」变得可感知——座位、专注状态、实时进度本身就是社交信号。架构上把「后端可云端化」当作设计约束，MVP 阶段就避免本地单机的架构陷阱，因此从第一天起就是客户端—服务端分离。

复盘

全栈一次成型，走完了 HCI 课程「需求观察 → 原型 → 可运行产品」的完整方法；后续方向：真实麦克风环境音（WebRTC 信令 + 空间音频）、正式产品迁移 PostgreSQL。

NO.17

对话归档台 · AI 对话总结 MVP

系统工程原型 HTML5Ollama本地大模型JSON 协议localStorage

概述

AI 产品「历史对话自动总结」功能的可交互 MVP：把一段长会话整理成结构化要点，每条要点可点击定位原文、可删除与重新生成；内置隐私开关与本地模型引擎，模型不可用时自动降级为浏览器规则摘要，内容全程不出本机；P2 追加归档库，跨会话搜索全部摘要要点、按会话聚合管理，形成单机全局记忆。

开发过程

从评估到立项：先按用户痛点、使用频率、开发成本、解决效果、潜在副作用五个维度评估「自动总结」值不值得做，结论是「应该做，但以手动触发的轻量 MVP 起步」——自动总结会改变用户行为、可能丢失细节，手动触发把选择权还给用户。

P0 落地：手动触发单会话摘要，输出结构化要点（核心结论 / 细节补充 / 待办行动三档），每条要点带原文锚点可定位核对；支持单条删除与重新生成；隐私开关默认手动触发、单会话关闭；固定标注「AI 生成，可能存在误差」。

引擎双降级：优先调用本机 Ollama（qwen3:8b）做真实摘要，模型输出约束为严格 JSON（标题 + 要点 + 锚点 + 等级）；模型不可用或隐私模式开启时，自动降级为浏览器本地规则摘要（关键词 + 句长打分提取重点句），演示永不中断。

P1 追加：自动归档（切换会话时后台为离开的会话生成摘要并缓存，localStorage 持久化，重新打开即见）与智能命名（模型顺带产出 ≤12 字会话标题，自动应用到自定义会话）。

P2 追加：归档库视图（顶栏一键进入）——统计全部会话归档情况，跨会话搜索每条要点（标题 + 内容，命中关键词高亮），按会话聚合主题标签，点击条目直接跳回对应会话。多端同步需要后端服务，本地单机版明确不做，作为边界记录在案。

设计思路

准确性与隐私是这类功能的两条生命线：锚点定位让「模型可能出错」变得可核实，隐私开关把「对话内容进模型」的合规风险交给用户决定。实现上坚持「降级链」——真实模型 → 规则引擎 → 演示数据，任何一层失败都能继续演示完整流程，这本身就是产品评审时的信心来源。

复盘

验证充分：解析器 17 项单测、真实模型链路输出 6 条要点（锚点全部落在消息范围内）、页面自检零 console 错误（归档库视图另跑桌面/移动自检同样零错误）。结论：把「AI 功能」做成「可演示、可降级、可离线」的工具，比一次到位更接近真实产品的落地节奏。
